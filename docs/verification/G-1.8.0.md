The procedure is [M10 acceptance](../M10_ACCEPTANCE.md), "The 1.8.0 release". The form of the record is the [1.7.0 record](G-1.7.0.md). The prior record is G-1.7.0.

## What 1.8.0 contains

From [the release notes](../RELEASE_NOTES.md#180):

- **R112, raised export limits.** The read-snapshot budget is 512 MiB (536,870,912 bytes), from 256 MiB, one budget for every
  export, render and library or bundle insert that takes a snapshot. The GLB visible-face cap is 600,000, the materialized face
  limit, from 100,000. The GLB manifest bound is 192 MiB, from 128 MiB. The capability output reports `limits.readSnapshotBytes`
  (536870912) and `limits.glbVisibleFaces` (600000). No file format, schema, document version or model limit changes. The
  owner raised the modeled memory ceiling to 8 GiB on 2026-11-06 ([R082w v4](R082w-memory-budget-v4.md#the-owners-decision)).
- **D-094, Select tool hint.** With saved-scene tabs visible, the hint no longer overlaps the status line.
- **D-095 and D-096, `NOT_FOUND`.** A scripted command, or a read-only query, that names a body, material, tag or component
  definition the document does not hold fails with `NOT_FOUND` and names it. A `tag.assign` to a tag that does not exist fails
  with `NOT_FOUND`. This changes an error code that callers see. Successful commands and queries are unchanged.
- **Documentation.** The README is a short overview with screenshots; [docs/README.md](../README.md) is the documentation index.
- **Schema.** None. 1.8.0 reads document versions 1 through 35 and writes 35 at most. The downgrade window is 1.7.0-1.

## Contradictions between sources

These are places where two sources disagree, or where a source's claim is not borne out by another. The record reports each one
and does not pick one silently. Items 1 to 6 are for the parent to decide or correct. This PR does not edit the files named in
them, except [R089.a](R089a-defect-triage.md), which gets the one RC line.

1. **The two acceptance tests are not in the Sanitized job.** [M10](../M10_ACCEPTANCE.md#the-180-release)'s Limits row expects
   `unique_limits_acceptance`, `snapshot_glb_limits_acceptance` and the export suites to pass "in the sanitized run of the pinned
   image", with their peak RSS and time. At the RC the export suites do pass there, but the two acceptance tests do not run in
   that job, and the RC evidence has no sanitized time or peak for them. The record states this as a gap. It is not resolved here.
2. **The 153,034 model's body count in the smoke label.** `glb/glb-checks.txt` says `bodies=17` for the 153,034-visible-face
   model. That text is a literal in `harness/smoke-180-glb.sh` (its `note` line). The export itself has 36 bodies, 18 geometry
   and 18 group (`glb/glb-export.json`), as the facts sheet says. The product output is right; the harness label is wrong.
3. **Rounding of the visible-face count.** The release notes and ADR 0162 describe the model as "153,000 visible faces". The model
