# The 1.4.0 group: release record

Date: 2026-10-29. **The release record is complete at the 1.4.0 release candidate
`9ed43c900739a04d450db32dcc9be80258bc5492` (RC1), and SketchyUp 1.4.0 is published.** On 2026-10-29
the owner approved the tag and the release, accepted the remote corpus gate (R086.h), accepted that
the native and dialog-audit cells that no CI line runs stay recorded as not run, and chose to ship
RC1 with D-070 and D-071 open. The annotated tag `v1.4.0` points at the RC, and the
[GitHub release](https://github.com/zygote55/sketchyup/releases/tag/v1.4.0) attaches the seven files
of the artifact manifest; see [Published release](#published-release). This record, as first merged
in [#517](https://github.com/zygote55/sketchyup/pull/517), said it awaited the owner; it is updated
here to the outcome.

The full tier passes at the RC. Twelve of its thirteen jobs passed on the first attempt; the
Wayland 2× job failed one check of `skp_import_dialog_tests` (a sampling window in the test, D-070,
Minor) and passed on the rerun of that job, so the CI verdict passes. The local walkthrough passes at
RC1. It ran the release artifacts twice with the same archive, package acceptance, and the pinned,
fresh and Qt 6.8 reference clean machines, each `--network none` and on its first attempt. Each
clean machine ran a new 1.4.0 smoke, the downgrade window and the D-036 PDF check. The provider
corpus passes ([R086.h](R086h-rc140-remote-evaluation.md), corpus v6, 24/24, no blockers). The
triage finds no release-blocking and no Major defect open. The hardware checks and the manual pass
that [ADR 0161](../decisions/0161-m9-hardware-evidence-waiver.md) waives were not run. They are
marked **Waived (ADR 0161)** below and stay **untested**; they are not claimed to pass.

The procedure is [M10 acceptance](../M10_ACCEPTANCE.md), "Required evidence at the RC" and "Release
record". M10 names one record for the group, so this record also holds the RC walkthrough, which
1.3.0 kept in a separate file ([F03-rc-1.3.0](F03-rc-1.3.0.md)). The record follows the 1.3.0
record, [F03-1.3.0](F03-1.3.0.md). [Machine-readable summary](G-1.4.0.json). Records written after
the RC, this one included, are evidence about the RC and are not part of its artifacts.

### Package acceptance

`packaging/arch/verify-package.sh` in `sketchyup-build:20261002`, with
`SKETCHYUP_PRIOR_RELEASE_PACKAGE` set to the published `sketchyup-1.3.0-1-x86_64.pkg.tar.zst`, whose

runner pointed at the RC worktree, with 5 GiB, 2 CPUs and two compiler jobs (1.3.0: 10 GiB, six

- **First start (2026-10-28 20:05, not counted as a run of the check).** `makepkg` stopped before
  building: it could not resolve `boost`, `eigen`, `opencascade` and `patchelf`, the IFC build's
  `makedepends`. CI's package job installs them first; the 1.3.0-era local runner did not, because
  1.3.0 had no IFC package. This is a harness fault, not a product defect.
- **Second start (2026-10-28 20:35 to 21:24).** The runner installs those four packages from the
  image's repositories, then runs the script unchanged. Exit 0 on its first build. Log
  `output.log` `c9b4370d…c167`; job log `bb960986…adb0`.

installs it, upgrades it to the RC's 1.4.0-1, and uses the published 1.3.0-1's CLI, unpacked
privately, for the format checks, as at 1.3.0.
