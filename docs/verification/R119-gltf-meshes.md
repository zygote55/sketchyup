# R119: glTF meshes used by one node import as groups (D-108)

timed out on every attempt (connection refused at the TCP level, and no ControlMaster socket at `~/.ssh/sketchyup-gpu.sock`).
D-108 stays open in the triage until that run passes. Machine-readable summary: [R119-gltf-meshes.json](R119-gltf-meshes.json).

## The rule (owner decision, 2026-11-08)

A glTF mesh used by one node imports as a plain group. Its bodies are children of that node's group, with no component
definition and no instance. A mesh used by several nodes becomes one component definition, with one placement per node,
as before.

The import counts the uses before it builds anything. `countUses` walks the same roots that `run()` visits, and counts
the visited nodes that use each mesh. It refuses the same repeated nodes and excessive depth that `node()` refuses, so no
refusal comes after a record is built.

## What changed in the outputs

| Output | Before | After |
| --- | --- | --- |
| A mesh used by one node | one component definition, a root group named after the mesh, one placement | loose bodies under the node's group; no definition, no instance |
| Import report `meshDefinitions` | one per mesh | one per mesh used by several nodes |
| Import report `meshGroups` | (not reported) | one per mesh used by one node (new key) |
| More than 4,096 meshes | refused whole: `Invalid component definition allocator or count` | meshes used once import; meshes used by several nodes are counted, and more than 4,096 is refused by name |
| Definition size limit (800,000 faces or vertices, R115) | applied to every mesh | applied only to a mesh used by several nodes; a mesh used once is limited by the unique limits and the one-body split (R113) |
| Name of a mesh used once | the root group of its definition | dropped; the node's name names the group, and the bodies keep `Primitive N` names |
| Materialized totals | one placement per node | a loose body counts once as unique and once as materialized, with no placement |

A glTF with only single-use meshes is unaffected by the count bound: a bound of zero admits it.

## Consequences the owner should know

- **Identical loose bodies re-import as a component.** The GLB exporter keys each glTF mesh by the content of its body
  (a SHA-256 of the body's positions, normals and coordinates). Two loose bodies with identical geometry therefore export
  as one mesh used by two nodes, and that imports as a component. The round trip keeps the geometry and the faces, but not
  the separate loose bodies. The fix belongs to the export's sharing, not the import, and is not made here.
- **A single-use mesh's name is dropped.** The mesh's root group is gone, so its name is not kept. The node's name names the
  group.
- **A single-use mesh now imports past the 800,000-face definition limit,** up to the unique limits (2,400,000 faces,
  vertices and wires) and the one-body split. That is the rule's consequence, not a regression.
