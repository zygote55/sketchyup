# SketchyUp 1.6.0: release record

Date: 2026-10-31. **The release record is complete at the 1.6.0 release candidate
`4e625298e7f0c0ab4339714019d61de323d1b9a1` (RC2), and SketchyUp 1.6.0 is published.** The full tier passes at RC2:
[run 41233571831](https://github.com/zygote55/sketchyup/actions/runs/41233571831) finished with conclusion success, and
every workload job passed on the first attempt ([CI at the RC](#ci-at-the-rc)). RC1 (`58afe4a6`) failed the Arch package
acceptance job on D-088, which the RC's own package check found. RC1 was replaced by RC2 before any release
([RC1 and RC2](#rc1-and-rc2)).

The owner chose "Release it, same permission" on 2026-10-31. That is the 1.5.0 permission of 2026-10-30, applied to
1.6.0: the live corpus run, accepting the corpus gate, and the tag `v1.6.0` and the GitHub release once every check
passes ([Owner decisions](#owner-decisions)). The record was first merged in [#558](https://github.com/zygote55/sketchyup/pull/558), before the tag was made. The tag and the release were made after that merge; see [Published release](#published-release).

The local walkthrough passes at RC2. It built the release artifacts twice with the same archive, and package
acceptance passed on its first try. It ran the pinned, fresh and Qt 6.8 reference clean machines, each
`--network none` and on its first attempt, with the 1.6.0 smoke, the downgrade window, the split-package rollback and
the D-036 PDF check. The provider corpus passes ([R086.j](R086j-rc160-remote-evaluation.md), corpus v6, 24/24, no
blockers). It ran at RC1, and the RC1 to RC2 change does not touch the corpus binary ([RC1 and RC2](#rc1-and-rc2)).
The triage finds no release-blocking and no Major defect open ([R089.a](R089a-defect-triage.md)). The hardware checks
and the manual pass that [ADR 0161](../decisions/0161-m9-hardware-evidence-waiver.md) waives were not run. They are
marked **Waived (ADR 0161)** below and stay **untested**; they are not claimed to pass.

The procedure is [M10 acceptance](../M10_ACCEPTANCE.md), "Required evidence at the RC", "The 1.6.0 release" and
"Release record". 1.6.0 is not a new Extended row. It carries the georeferenced orthophoto as a reference image
(R107.b2.1 and R107.b2.2, schema 35, viewport only), the frame credit in the camera view (R107.c3 and R107.c3.1), the
user guide viewer and guide text (R107.e2), the CI flake work (PRs #547 and #548) and the defect fixes D-082 to D-085
and D-088. The prior record is [G-1.5.0](G-1.5.0.md).

## Versions and format

The release notes ([Versions](../RELEASE_NOTES.md#160)) and the support matrix state the versions. In short:
`sketchyup` 1.6.0-1 and `sketchyup-ifc` 1.6.0-1; the native document is schema 35 at most, in SKUPDOC container version 2,
and reads versions 1 through 35; saves record the writer `SketchyUp/1.6.0`. The public schema changed only for the native
document (`sketchyup-document-v35`). The MCP, inspection, transaction, recipe and other public schemas are unchanged from
1.5.0. The release adds no third-party code: the orthophoto reader uses the inflater and the texture decoders 1.5.0 ships.

A document with no georeferenced image is written exactly as 1.5.0 writes it. A georeferenced image is written at schema
35, which 1.5.0 refuses.

## Upgrade and rollback

[RELEASE_NOTES.md](../RELEASE_NOTES.md#upgrade-from-150-1) is the user-facing source. At RC2:

- `pacman -U sketchyup-1.6.0-1-x86_64.pkg.tar.zst` upgrades 1.5.0-1. For the IFC and STEP helper, also install `sketchyup-ifc-1.6.0-1-x86_64.pkg.tar.zst`. Package acceptance upgrades a 1.5.0-1 package built from the release source to 1.6.0-1, and checks that the published 1.5.0-1 CLI refuses the schema-35 fixture unchanged and opens the schema 27 to 34 fixtures unchanged.
- Rollback: remove `sketchyup-ifc` first if it is installed (`pacman -R sketchyup-ifc`), because it requires the exact `sketchyup` version and pacman refuses the rollback while it is installed. Then install `sketchyup-1.5.0-1-x86_64.pkg.tar.zst` with `pacman -U`. This is D-071's step.
- A document with a georeferenced reference image is schema 35 and does not open in 1.5.0. Copy such a document before you open it in 1.6.0 if you may need 1.5.0. A document without one is written at its usual schema and opens in 1.5.0.
