### RC2 provider corpus (D-041)

The orchestrator ran the owner-approved corpus v4 at RC2 with the `chatgpt-astra` profile. This
walkthrough made no provider call. The run failed: **resize, advanced and site scored 0/3 each.**
Root cause: `OpenAiConversation::decode` (`src/integrations/openai_provider.cpp`) rejected a
reply that batches several calls when the batch combined `transaction.inspect` with
`transaction.diff`, so every such reply failed the turn. It is a product defect, recorded as
[D-041](R089a-defect-triage.md#triage-table) (Major, found by the gate). The fix is PR #344 (head
`522fe3cd`: `openai_provider.cpp` and a test), which becomes RC3 once its CI passes. The private
run evidence (transcripts, reports and provider details) stays outside the repository; only the
counts and the root cause are cited here.

### Deviations from the 1.1.0 procedure

- **CI shape.** Ten jobs instead of four; every CI native line ran at RC2.
- **Development build target set.** As at RC1: native fixtures out of `all`, 27 native targets
  built explicitly (disk). The 23 GB tree was deleted after the runs.
- **Row re-run.** F02's fractional CI lines and the F02 detail replace F01's sheet suites at 1.5
  and the R092.d detail.
- **New clean-machine steps.** The F02 smoke in the lifecycle, and a Qt 6.8 check that writes the
  D-036 PDFs and runs the downgrade window with the reference-built 1.2.0-1, 1.1.1-1 and 1.0.1-1.
- **Reference prior package.** The Qt 6.8 lifecycle upgrades from the reference-built 1.1.1-1
  (F01.a), the release before 1.2.0; at 1.1.0 it upgraded from 1.0.1-1.
- **Scheduling.** The cache preps and the reference build ran without the shared lock, alongside
  package acceptance (each container has its own CPU and memory limits).
- **Disk stop and resume.** After the Qt 6.8 checks, the queue's disk check stopped it at 11 GB
  free on `/home`. This run's own files were about 3 GB; the dip came from other work on the host.
  Free space was back to 39 GB minutes later, and the queue resumed at the development build
  (lowest point afterwards 25 GB).
- **Container users.** The jobs run as root inside the containers (pacman needs it); outputs were
  given to uid 1000 afterwards.

### Runs and limits

- **Wide runner:** the RC1 copy of `scripts/run-container-check.sh` with `source_root` pointed at
  RC2's detached worktree: six CPUs 6–11, 10 GiB, `-j4`, `--cap-add=SYS_PTRACE`.
- **Clean machines:** R087.u method, two CPUs, 2 GiB, no network, from caches prepared with the
  network. The reference cache prep's log is byte-identical to 1.1.0's and RC1's (`92e96140…`).
- **Packages in the native image:** `native.yml`'s CI package set without Blender, plus
  `xorg-setxkbmap` and `git`, from the pinned 2026-10-02 archive.
- **Source tree:** `git archive` of RC2, so the M5 and M6 `sourceCommit` fields are null.
