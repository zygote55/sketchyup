# F02 — Release-candidate walkthrough for 1.2.0

2026-10-17. The release candidate is `main` at
`71a6b4f3e6068f3d8a4924d063faf30c7ce797fb` (merge of PR #342). Every check below ran
against this commit or its artifacts. The procedure is [M10_ACCEPTANCE.md](../M10_ACCEPTANCE.md)
as it stands at the RC: "Release-candidate freeze", "Owner waiver of hardware evidence", "Owner
trim of the local walkthrough" and "Required evidence at the RC", with the method of the
[1.1.0 walkthrough](F01-rc-1.1.0.md). [Machine-readable record](F02-rc-1.2.0.json).

This is the RC walkthrough, not the release record. The release record (`F02-1.2.0.md`) also
needs the provider corpus run at this RC and the owner's acceptance. The R094 acceptance record
is [R094.h](R094h-configurable-components.md).

**Result: the RC does not pass as documented.** CI passes all 10 jobs at the RC. Package
acceptance, both current clean machines, the 47 non-CI native cells, the dialog audit, the F02
fractional lines, the M5–M8 studies and the F02 detail all pass on the first attempt. The Qt 6.8
reference machine fails: **the RC archive does not compile against Qt 6.8.0**, the minimum that
`CMakeLists.txt` and the support matrix declare. It is recorded as
[D-037](R089a-defect-triage.md#triage-table) (Major). Shipping needs an owner decision and a new
RC; see [Failures](#failures) and [Open for the owner](#open-for-the-owner). The provider corpus
row is pending owner approval.

## Owner trim of the local walkthrough

The owner's 2026-10-15 rule ([M10, "Owner trim of the local walkthrough"](../M10_ACCEPTANCE.md#owner-trim-of-the-local-walkthrough))
applies to every later M10 release, and is in the M10 text the 1.2.0 package ships. CI run
[39031115333](https://github.com/zygote55/sketchyup/actions/runs/39031115333) on `71a6b4f3`
passed all 10 jobs, so it is the evidence for every step the workflow runs with the same
invocation.

- **Ran locally:** the release artifacts, package acceptance, the clean machines (pinned, fresh
  and the Qt 6.8 reference, with the sheets smoke, MCP `tools/list` and a new F02 smoke), a
  Qt 6.8 downgrade-window check, the 47 native cells that CI does not run, the dialog-audit cells
  that CI does not run, F02's fractional CI lines, the M5–M8 studies, and the F02 detail (the
  headless F02 `ctest` entries with `-V`).
- **Covered by CI run 39031115333, not repeated locally:** `ctest --preset dev` (210/210), the
  opt-in `*_real` consumers (Blender 9/9, DXF 1/1, PDF 2/2), the CI line inventory ("Inventory
  matches: 514 lines (509 distinct)"), MCP schema validation, shipped recipes, generated reference
  and API schema checks, every native line of the X11 1×, X11 2×, Wayland 1× and Wayland 2× jobs
  (337 lines, among them every F02 suite in all four cells), the AT-SPI bridge in four cells,
  keyboard layouts, the CI audit cells (inventory, X11 2× and Wayland 1×), the fractional 1.5×
  and 1.75× lines, the Blender worker and M5 with Blender, every step of the sanitize job (68/68,
  110/110, 7/7, 1/1 and its native lines), Blender interoperability and the CI package acceptance
  (210/210).
- **Development build:** built only (`cmake --preset dev -DSKETCHYUP_NATIVE_FIXTURES_IN_ALL=OFF`,
  then `all` and the native targets the local runs use; see [Deviations](#deviations-from-the-110-procedure)).
  Of `ctest` it ran the nine F02 entries with `-V` and, inside the M6 study, all 210.
- **Not run locally:** the sanitized build, and so the sanitized cells that are not CI lines. The
  sanitize job passed in CI.

## Failures

One product defect; no harness error and no retry.

- **Qt 6.8 reference, build of 1.2.0-1 (D-037).** `run-build.sh build-reference` on the
  2024-10-15 snapshot (Qt 6.8.0-1, GCC 14.2.1) stopped after about 9 minutes at target 255 of
  726: `src/app/window_sidebar.cpp:112:41: error: 'Orientation' is not a member of
  'QAccessible::Attribute'`, the same at line 115, and `makepkg` exited 4. Qt 6.8.0's
  `qaccessible_base.h` (from the snapshot's `qt6-base-6.8.0-1` package) declares
  `enum class Attribute { Custom, Level }`; Qt 6.11.2's adds `Locale` and `Orientation`. The code
  came in R094.a (`c3cfd6ac`, sidebar handles exposed as split panes). The build is
  deterministic, so it was not repeated. **Classification:** product defect on a declared
  supported configuration, [D-037](R089a-defect-triage.md#triage-table) (Major). No product code
  was changed here. Because no 1.2.0 runs on Qt 6.8, the reference lifecycle and the D-036 check
  on Qt 6.8 did not run; the downgrade-window half of the Qt 6.8 check ran with saves from the
  pinned package.

Every other local run passed on its first attempt.

## Deviations from the 1.1.0 procedure

- **CI shape.** 1.1.0's CI was four jobs; at this RC it is ten (the native lines split into six
  jobs). The trim's coverage is unchanged: every CI native line ran at the RC.
- **Development build target set.** 1.1.0 built the full dev tree (about 37 GB). With about 45
  GB free on `/home`, this run configured `cmake --preset dev -DSKETCHYUP_NATIVE_FIXTURES_IN_ALL=OFF`
  (same compiler flags; it only drops the 97 native fixtures from `all`, as R094.h's host build
  did) and built `all` plus the 27 native targets the local runs use: the 19 pattern suites,
  `native_accessibility_audit`, `component_parameter_input_tests`, `m4_workflow_tests`,
  `assistant_panel_tests`, `m6_workflow_input_tests`, `m6_workflow_tests`, `m8_exchange_tests`
  and `sketchyup-cli`. The tree was 23 GB, and was deleted after the runs.
- **Row re-run.** F01 kept its four sheet suites at 1.5 locally. This run kept F02's fractional
  CI lines (`component_parameter_input_tests` at 1.5 on both platforms) instead, and replaced the
  R092.d detail with the F02 detail (nine headless F02 `ctest` entries with `-V`). The sheet
  suites at 1.5 are CI lines and passed in CI.
- **New clean-machine steps.** The lifecycle adds an F02 smoke (assemblies rebuilt with the
  installed CLI, the schema-28 fixture, MCP parameter queries). A new Qt 6.8 downgrade-window
  check installs the reference-built 1.1.1-1 and 1.0.1-1 in turn and validates 1.2.0 saves.
  Because of D-037 its 1.2.0 saves come from the pinned image's accepted package
  (`make-saves.sh`) rather than a reference-built 1.2.0.
- **Reference prior package.** The Qt 6.8 lifecycle would have upgraded from the reference-built
  1.1.1-1 (F01.a, `8e7ca784…`), the release before 1.2.0. It did not run (D-037).
- **Scheduling.** The three cache preps and the reference build ran without the shared lock,
  alongside package acceptance, and the saves and Qt 6.8 checks alongside the development build
  (each container has its own CPU and memory limits). The 1.1.0 queue ran them under the lock.
- **Container users.** As at 1.1.0, the jobs run as root inside the containers (pacman needs it).
  Every job ended by giving its output to uid 1000, and the remaining root-owned files were
  chowned by a container after the runs.

## Runs and limits

- **Wide runner:** a copy of `scripts/run-container-check.sh` outside the repository (the 1.1.0
  copy with `source_root` pointed at the RC's detached worktree, SHA-256 `78b7e3c3…2ca8d`): six
  CPUs 6–11, 10 GiB, `-j4`, a 10 GiB free-memory precondition, `--cap-add=SYS_PTRACE`. It ran
  package acceptance, the development build, the native cells, the audit, the studies and the
  F02 detail, one container at a time.
- **Prior release in package acceptance.** The verified 1.1.1-1 copy was mounted at
  `/work/package/release/`, as at 1.1.0.
- **Clean machines.** R087.u method: two CPUs, 2 GiB, no network, from a cache prepared with the
  network. The reference cache prep's log is byte-identical to 1.1.0's (`92e96140…`).
- **Packages in the native image.** Each job installed `native.yml`'s CI package set (without
  Blender), plus `xorg-setxkbmap` and `git`, from the pinned 2026-10-02 archive.
- **Source tree.** The native jobs used `git archive` of the RC commit. The tree has no `.git`, so
  the M5 and M6 `sourceCommit` fields record as null.
- **Disk.** `/home` had 45 GB free at the start, 28 GB at the lowest (after the development
  build) and 41 GB after the build trees were deleted.

Large logs and evidence are in `~/sketchyup-verification/rc-1.2.0/` and are not published. The JSON
record lists the SHA-256 of each one it cites.
