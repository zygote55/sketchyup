# Own-process DRM memory evidence

The real-model benchmark now reports the current process's Linux DRM memory counters alongside process RSS and retained model/history storage. It reads only this process's DRM descriptors, bounds descriptor enumeration and read size, deduplicates kernel clients, stores counters as decimal strings and preserves unavailable/invalid data. Resident regions may overlap or be shared, so their aggregate is explicitly an upper bound and is never added to process RSS. These observations do not account for every driver allocation.

The parser and benchmark source `296bb8e74224181b5e030fd2cb88c5f28882bd84` passed normal and ASan/UBSan parser checks with leak detection, plus twelve software fixture checks and a Release parser check. Software rendering reported DRM memory unavailable, rather than zero. The initial collector incorrectly expected obsolete CTest summary wording; that failure and the correction from unchanged source/actual passing logs remain separate records.

The [version-one memory budget](R082w-memory-budget-v1.md) was frozen at 06:45:07 UTC before this AMD campaign, with SHA256 `5f4c4a11f9f1d8a0a7b11b7e417e5036baa7a64d7e0c5afb15a80368ba8fe8dd`. The earlier roadmap planning omitted numeric memory ceilings; these new ceilings cannot retrospectively accept older measurements. They require at most 1 GiB process RSS for the supported 100k family, 3.5 GiB for the private million-triangle family, 2 GiB of reported resident DRM regions, and 64 MiB sampled growth/retained history. The four-GiB execution cap is distinct from acceptance.

All thirteen fresh AMD cases passed the prospective memory checks: five small smokes, five 100k families and three private million-triangle runs. Each run performed five history cycles, 500 edits, 1,000 rendered undo/redo frames and 65 memory checkpoints, with 67 driver-memory observations. The 871-observation supplementary audit confirms every reported client and region contains resident counts. Million-triangle peak process RSS was 3,176,275,968–3,176,910,848 bytes, resident-region upper bound 501,121,024 bytes, sampled growth 21,266,432–21,368,832 bytes and retained history 1,632,500 bytes. Full viewport p95 was 26.31–27.57 ms and edit-to-GPU-complete p95 94.52–96.78 ms. The enclosing edit measurement took 120.12–122.79 ms; these different timing scopes are retained. Large inference probes reported 61 truncated queries. No blanket performance acceptance follows from the memory result.

The disposable benchmark binary `064cfacacbd3c354e15b585021addb07cce394b071c64b7d3251a82c9b37e84e` used frozen, disclosed private sizing overlays and the baseline renderer, excluding the rejected VAO candidate. The GPU was a Navi21 device on CachyOS with Qt6.11.2, development Mesa26.3 and kernel7.2.7, in an already-awake X11 session at1920×1080. Driver-versus-PCI marketing names differ in the retained preflight. This is supplementary hardware evidence, not a newly designated reference platform. No desktop, host package, RAM, swap or production-limit changes were made. The laptop's displays were asleep, so the Intel repeat ran zero cases.

After collecting those reports, review identified an incomplete-counter aggregation case: one client with resident data could hide another recognized client without it. Source `21e7622254d294c7ae08ee98ce84f19b06dfefd4` now marks missing client/region resident counters partial and leaves the aggregate unknown, while preserving an explicit zero. New tests fail against the original header, then pass normally and under ASan/UBSan with leaks enabled. All 871 original hardware observations independently contain complete counters, so their recorded values remain usable. The final parser then passed twelve fresh software fixture checks and a Release parser check, followed by a fresh thirteen-case AMD repeat using binary `d6b416353df8ffb9c5cfd7e842e03533e77feacdf73d530f4576a093821c66b8`. All 871 new driver observations contain complete resident counters and all thirteen cases satisfy the same frozen memory budget. Million-triangle RSS was 3,176,067,072–3,176,419,328 bytes; full viewport p95 was 26.27–27.05 ms and edit-to-GPU-complete p95 97.01–98.30 ms. The enclosing edit p95 was 122.89–125.43 ms, and large inference probes still reported 61 truncated queries. The original artifact, final parser artifact and their raw reports remain distinct in the [identity and artifact record](R082w-driver-memory.json).

These are finite-scope memory measurements. Public million-triangle sizing, current-source Intel/AMD/reference-platform acceptance, complete R082 behavior and the M9 release gate remain open.
