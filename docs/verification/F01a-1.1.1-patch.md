### Upgrade from the published 1.1.0-1

The check installs the downloaded 1.1.0-1 package with `pacman -U`, as root in a
disposable container, and runs the application as an unprivileged user:

1. `pacman -Q` reports `sketchyup 1.1.0-1`; `pacman -Qkk` finds 251 files, none altered;
   `sketchyup-cli --version` and `sketchyup --version` report 1.1.0.
2. It seeds preferences (`SketchyUp.conf` with a sentinel key, theme, text size, reduced
   motion, recovery interval and field of view) and data and cache sentinels.
3. The 1.1.0 CLI opens the retained `tests/fixtures/drawing-sheets-v27.sketchyup` and saves it
   to a new document: writer `SketchyUp/1.1.0`, document chunk `json-v27`, and the same
   inspection as the fixture.
4. `pacman -U` upgrades to 1.1.1-1. `pacman -Q` reports `sketchyup 1.1.1-1`; both
   `--version` commands report 1.1.1. The preferences file is byte-identical to the
   seeded one, and the data and cache sentinels remain.
5. The 1.1.1 CLI validates the 1.1.0 document and reads the same inspection that 1.1.0
   read. It saves it to a new path; that file has the writer `SketchyUp/1.1.1`, chunk
   `json-v27`, passes `--validate-native` and reopens with the same inspection. The 1.1.0
   document is unchanged.

## Failures

Three first attempts failed. None is a product defect; each is recorded with its log.

- **Package acceptance, attempt 1 (`p111-package`): `drawing_sheet_io` failed in the
  prior-labeled build's `check()`.** The run set `SKETCHYUP_PRIOR_RELEASE_PACKAGE` to the
  published 1.1.0-1. That variable enables the [ADR 0163](../decisions/0163-documentation-sheets.md)
  downgrade-window check, whose test asserts "The prior release rejects schema 27 with items
  and leaves the file unchanged". 1.1.0 reads schema 27, so this assertion cannot hold for any
  1.1.x prior; the check is defined for a release before schema 27. The other 200 tests
  passed. Attempt 2 used the published 1.0.1-1, as CI does (`.github/workflows/native.yml`),
  and passed; the upgrade from the published 1.1.0-1 binary is tested by the real upgrade
  instead. Classification: configuration of the check, deterministic, not a product defect.
- **Real upgrade, attempt 1 (`p111-upgrade`): harness error.** The script looked for the
  string `sketchyup-document-v27` in the saved file, but a v27 container records its
  schema as the chunk encoding `json-v27`. The 1.1.0 install, preference seeding and save
  had passed. Attempt 2 checks the chunk encoding and passed.
- **Qt 6.8 reference exports, attempt 1 (`qt68-reference`): harness error.** `pacman -Q
  qt6-base` ran before any package had installed Qt and stopped the script. Attempt 2 made
  that line non-fatal and passed.

## The provider corpus

The patch changes no assistant, provider, tool or schema code. The provider corpus
`inputSha256` values hash the fixture container bytes, which change with the writer string
`SketchyUp/1.1.1`. All eight were regenerated with `provider_trial --describe` in both
corpus files; every `promptSha256` is unchanged, as in
[R089.b](R089b-release-version.md) and R089.g. The owner approves live provider runs case by
case; none ran.

## Package acceptance prior rule

For 1.1.1-1, `verify-package.sh` already labels the prior build 1.1.0-1 (the first `pkgrel`
of a patch version `x.y.z` upgrades from `x.y.(z-1)-1`). The patch adds the published
1.1.0-1 to `released_packages` and pins its SHA-256 for the prior-release format check, so a
future 1.2.0-1 upgrades from it. The real upgrade above is what tests the published 1.1.0-1
binary.

## Runs and limits

- **Host.** Builds used at most six jobs. The headless and sanitized builds and tests ran on
  CPUs 0–5 while the first package job held CPUs 6–11.
- **Containers.** One at a time, through the shared local-check lock. Package acceptance used
  the wide copy of the runner (six CPUs 6–11, 10 GiB, `-j4`) with its source root pointed
  at the patch worktree; it still prints the standard banner. The upgrade check used the
  standard runner (one CPU, 4 GiB). The Qt 6.8 package build used the 1.1.0 reference
  method (networked to the dated archive only); the export runs and the pinned smoke ran with
  `--network none` (2 CPUs, 2 GiB).
- **Not covered.** Qt 6.8.1–6.10 were not run. The desktop Print path through `QPrinter` is
  not repaired, and on Qt 6.8.0 without a time zone the XMP dates stay empty; the release
  notes say so. The desktop sheet export was not exercised on Qt 6.8; it calls the same
  export function as the CLI.
- **Not repeated.** The native suites, the AT-SPI and dialog audits, the studies, the fresh
  clean machine, the full clean-machine lifecycles and the hardware checks of the 1.1.0
  release record were not re-run. The patch changes two PDF export paths, a new PDF repair
  function, their tests, version strings and documents. CI on the pull request runs the
  native jobs.
