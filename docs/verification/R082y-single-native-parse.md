# Parse native payloads once

Container decoding previously parsed the model JSON once to inspect its asset declarations and again to restore the records. The container path now passes the already parsed root to the same internal record decoder used by raw JSON. Input lengths, schema versions, fields, records, assets, topology and model limits still validate before publication; public APIs and production sizing remain unchanged. Corrupt records are rejected through both raw and checksum-correct packaged paths.

Tested source `c584ff50cf54d5ba8df099cdd74b0a108430732d` builds on PR252. Frozen qualification checked all 306 compiled runtime inputs with ten disclosed overlays. All 38 normal and 38 ASan/UBSan regressions passed with leak detection, including native migrations, persistence, recovery, components, private transactions and public caller ownership. The source cache was restored. Original logs and input hashes are retained alongside this record.

The controlled Release comparison used the same canonical 70,248,107-byte million-triangle file and identical private sizing, measuring three sequential warm double-parse controls followed by three single-parse candidates. Only the two decoder implementation files changed between variants. Every durable save matched the canonical bytes and hash. Control opens took 5.706–5.732 seconds; candidate opens took 4.312–4.330 seconds. Candidate saves took 4.230–4.262 seconds. Peak RSS decreased from 1.819–1.821 GB to 1.084 GB. All three candidate opens and saves meet the unchanged five-second target for this measured warm core workload.

The original comparison measures warm synchronous core work, excluding UI responsiveness. A separate frozen follow-up uses the same candidate binary and canonical bytes, with a fresh owned inode for each cold case. After fsync and per-file fadvise, mincore verifies all 17,151 input pages nonresident immediately before launch. All three verified file-cache-cold opens take 4.259–4.282 seconds, saves 4.097–4.126 seconds, and durable bytes match exactly. Paired warm opens take 4.228–4.244 seconds and saves 4.109–4.158 seconds. Peak RSS is 1.086–1.088 GB. This qualifies input-file OS data-page residency only; storage-controller caches, executable/library pages and native UI are not claimed cold. The benchmark's original advisory-only coldCacheVerified=false field remains unchanged; the separate outer residency proof supplies the stronger file-page observation. Three observations do not qualify a percentile or a general timing guarantee. The private million-triangle file does not promote public limits. The container used four GiB RAM, no extra swap, eight fixed CPUs and two compiler jobs; measurements ran on CPU8 to avoid the bounded provider client on CPU0. Disk scratch, fixture identity, control inputs, restoration and original binary hashes remain recorded. Current-source native UI checks and the full R082/M9 acceptance gate remain open. No global cache flush or display wake was used.
