## Failures

Two: a harness error, and one product defect found by the Qt 6.8 reference (D-036).

- **Clean machines, attempt 1 (pinned and fresh): MCP `tools/list` check failed.** The new step
  started `sketchyup-cli --mcp --input <model>` without an outcome directory. The CLI exited
  1 before reading the request, with `{"code":"INVALID_REQUEST","error":"Choose an explicit
  input model or create with an output, and an outcome directory","status":"failed"}`, and
  the step recorded all 8 sheet queries as missing. That is the documented `--mcp` contract
  (`tests/mcp_tests.cpp` always passes `--outcomes`). The step does not stop the lifecycle,
  and every other attempt-1 step passed on both images (`lifecycle=pass`), with the same
  package, closure, migrations, sheets smoke and upgrade results as attempt 2.
- **Attempt 2 (pinned and fresh):** the harness added `--outcomes`, and the whole lifecycle ran
  again in fresh networkless containers. Every step passed, including
  `mcp-sheet-queries=pass`. The pinned and fresh results are from attempt 2. The
  attempt-1 harness and logs are kept with the evidence. The Qt 6.8 reference ran later with
  the attempt-2 harness.
- **Qt 6.8 reference, attempt 1: malformed PDF Info dictionary (D-036).** Every lifecycle
  step passed (`lifecycle=pass`). The host Poppler check then found that the opted-in sheet
  export, written by Qt 6.8.0, has an Info dictionary without its closing `>>` and with the
  dates `D:00000000-1-1-1Z`. `pdfinfo` 26.08.0 reports 48 "Dictionary key must be a name
  object" syntax errors (at bytes 237–254) and cannot read Title, Creator, Producer or the
  dates. The 2 A3 pages, the text, the embedded fonts and the attached
  `sheet-export-report.json` are intact, and the file matches its report's SHA-256. The
  pinned (Qt 6.11.2) and fresh (Qt 6.12.0) PDFs have no syntax error.
- **Qt 6.8 reference, attempt 2 (to classify):** the whole lifecycle ran again in a fresh
  networkless container with the same packages. Same steps and log. The PDF differs only in
  its random XMP DocumentID and shows the same 48 errors. **Classification:** deterministic
  product defect on Qt 6.8 only, recorded as
  [D-036](R089a-defect-triage.md#triage-table) (Minor). It is likely a Qt 6.8.0 `QPdfWriter`
  bug (not confirmed). `src/io/measured_export.cpp` uses `QPdfWriter` the same way and was not
  checked. **Owner decision (2026-10-15):** ship 1.1.0 with D-036 recorded, keep the support
  matrix's Qt 6.8.0–6.12.0 claim, and fix it in 1.1.1. No new RC.

Every other local run passed on its first attempt.

  in `/work/package` (the first RC's run overwrote its copy there after the check).

  The Qt 6.8 reference builds used four CPUs, 4 GiB and two compiler jobs, as at 1.0.0.

  (without Blender), plus `xorg-setxkbmap` and `git`, from the pinned 2026-10-02 archive.
  So at-spi2-core and Poppler came from that archive, and no host files were mounted. The
  sheets-smoke PDFs were checked with the host's Poppler 26.08.0.

  `.git`, so the M5 and M6 `sourceCommit` fields record as null.
