# Bounded planar DXF source parsing

R077.a, 2026-10-07. `parseDxf` captures an explicit 2D subset as immutable source
values; it performs no IO, block resolution, script execution or native mutation.
ASCII DXF versions AC1009 (R12), AC1015, AC1018, AC1021, AC1024, AC1027 and AC1032
are supported. Text must be UTF-8 (an optional BOM is accepted); legacy code-page
bytes, binary DXF, DWG and unknown versions reject. DXF Unicode escape notation is
retained as literal text in names; it is not decoded. This is not full CAD fidelity.

Supported model-space entities are LINE, ARC, CIRCLE, LWPOLYLINE and ordinary 2D
POLYLINE/VERTEX/SEQEND. Geometry must lie in world XY with +Z extrusion and zero
thickness. Closed flags and signed bulges are retained; arcs preserve their centers
and signed sweep, including zero-degree crossings. Width/elevation/3D/mesh/curve-fit
polyline variants and unsupported extrusion are omitted with explicit reason counts.
Paper-space entities and unsupported types (including INSERT, TEXT, dimensions,
hatches and splines) are counted without resolving external data. Blocks, objects
and other unhandled sections are counted as omitted group pairs. Appearance,
application metadata and layer-style loss counts are explicit.

Layer names/assignments, frozen/off visibility and locked flags are captured. Missing
layer declarations create named source layers with a notice. Units use $INSUNITS
for inches, feet, millimetres, centimetres and metres. Missing, unitless or other
unit codes require an explicit caller scale; overrides are reported. Scales must
be finite, between 1e-6 and 1e6 metres per source unit. All converted geometry and
conservatively bounded arc extents fit the native coordinate range.

Limits: 64 MiB text; one million lines checked before splitting; 4,096 characters
per line; 16 sections; 4,096 header variables; 100,000 records per section and
expanded segments; 1,024 layers; 256 UTF-8 bytes per name; 128 distinct unsupported
entity/reason keys. Group-code/value pairs, section termination, EOF, singleton
fields, finite numbers, polyline vertex counts and SEQEND are validated. Malformed
supported geometry rejects; omission reports never claim it was imported.

[LWPOLYLINE](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm),
[ARC](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-0B14D8F1-0EBA-44BF-9108-57D8CE614BC8.htm)

Independent R12/R2018 drawings were generated by ezdxf 1.4.4 using
`tests/dxf_reference_fixture.py`. The checked-in fixtures require no Python package
at runtime or in CI. Their dimensions, 20-degree arc, half-circle bulge, closed
polylines, layer state and omitted text/paper-space records have independent test
oracles. ezdxf is optional regeneration tooling, not an application dependency.
Normal and sanitizer malformed-input/unit/bulge tests accompany the fixtures.
Native conversion, export and UI/CLI acceptance remain subsequent R077 slices.
