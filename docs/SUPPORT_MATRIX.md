# SketchyUp 1.6.0 support matrix

SketchyUp 1.6.0. This is the support declaration for the 1.6.0 release. It is the 1.5.0 declaration plus the
georeferenced orthophoto as a reference image (R107.b2, part of C06, which stays Investigate; viewport only), the frame
credit in the camera view (R107.c3 and R107.c3.1), and the in-app user guide viewer and guide text (R107.e2). The provider
profile is evaluated with corpus version 6; the tool surface did not change, so the corpus stays at version 6 and only its
writer-dependent inputs are re-pinned. No other supported configuration changed. The 1.5.0
declaration is the 1.4.0 declaration plus the 1.5 follow-ups (STEP restart-and-exclude, STEP speed and entity cap, render limits,
catalog progress and Cancel, and the Styles dialog gaps), the GeoTIFF elevation import (R107.b, part of
C06, which stays Investigate) and the source credits in exports (R107.c). The 1.4.0
declaration is the 1.3.0 declaration plus the 1.4.0 group of Extended rows: IFC and STEP exchange (F04), camera paths
and batch presentations (F05), custom styles and asset catalogs (F06), quantities, reports and
schedules (F07), `.skp` import (C01, import only), offline geographic coordinates (C06, offline
only) and the helper process sandbox (R109). The provider profile is evaluated with corpus
version 6 at the release candidate. No other supported configuration changed. The 1.3.0
declaration is the 1.2.0 declaration plus terrain and site tools, Extended row F03, and the
provider profile evaluated with corpus version 5. The 1.2.0
declaration is the 1.1.x declaration (1.1.1) plus configurable components, Extended row
F02, and the provider profile evaluated with corpus version 4. The 1.1.x declaration is the 1.0.x declaration (1.0.0, 2026-10-13) plus documentation
sheets, Extended row F01.
**Supported** means the configuration has release evidence. **Untested** means no
evidence exists for this release; it is neither claimed to work nor known to fail.

- **Supported:** Arch Linux x86_64 with the `sketchyup` 1.6.0-1 package, Qt 6.8.0
  through 6.12.0 and an OpenGL 3.3 core-profile driver. Omarchy/Hyprland on Wayland
  is the primary desktop; the Qt X11 path is also tested. Ordinary modeling needs
  no network, account, provider or Blender. The assistant's supported provider is
  OpenAI through a ChatGPT-plan sign-in. Documentation sheets (F01), configurable
  components (F02) and terrain and site tools (F03) are supported with the limits listed under
  [Exchange boundaries](#exchange-boundaries). The 1.4.0 group rows (F04 to F07, `.skp` import
  under C01, offline coordinates under C06 and the helper sandbox under R109) are supported with
  the limits listed there, and they are released only through the M10 gate. The 1.5.0 items are
  supported with the limits listed there; the GeoTIFF elevation import is shipped as part of C06, whose
  class is unchanged until R107.d. The 1.6.0 items are supported with the limits listed there. The orthophoto is
  viewport only: its credit reaches no export or frame.
- **Untested**, by owner waiver ([ADR 0161](decisions/0161-m9-hardware-evidence-waiver.md)):
  Intel graphics performance, X11 output hotplug, suspend/resume, a physical 150%
  output, physical pointer capture, input methods, automatic X11 output placement,
  D-020 on Hyprland and an interactive Orca session.
- **Experimental:** the local Ollama assistant adapter ([ADR 0160](decisions/0160-provider-scope-for-1-0.md)).
- **Not in this release:** the Investigate rows of the [scope matrix](SCOPE.md) that were not
  delivered: Ruby extensions (C02), DWG (C05), collaboration (C07), the Dynamic and Live Component
  formula mapping (R104.b), hosted-asset adapters beyond user downloads (C04, R105.b to R105.d),
  geocoding (C06, R107.d), and an orthophoto in exports and frames (R107.b2 places it in the viewport only). Native `.skp` or DWG
  support beyond the `.skp` import, `.skp` export, and full SketchUp parity are not claimed.

## Release gate and untested configurations

The [59 Core rows](SCOPE.md) are the 1.0 acceptance scope, not a claim of full
SketchUp parity. The M9 gate requires performance, accessibility, recovery,
provider, package and documentation evidence at the release candidate, plus the
aggregate M0–M9 audit. That record is [verification/M9.md](verification/M9.md). No
screenshot, source archive, passing subset or external render substitutes for it.

The owner waived the remaining physical and hardware checks and the manual walkthrough
on the installed release candidate for 1.0 ([ADR 0161](decisions/0161-m9-hardware-evidence-waiver.md)).
Those checks are **untested**, not passed: Intel campaigns, X11 hotplug, suspend/resume,
a physical 150% output, physical pointer capture, input methods, D-020 on Hyprland,
automatic X11 output placement and an interactive screen-reader session. The owner tests them in
daily use. The automated release-candidate checks stay required.

Documentation sheets (F01) are gated separately by [M10 acceptance](M10_ACCEPTANCE.md),
at the 1.1.0 release candidate. The same waiver applies there: the checks listed above
stay untested, and the automated checks, including the sheet suites on X11 and Wayland
at 1× and 2×, stay required.

Configurable components (F02) are gated the same way at the 1.2.0 release candidate,
with the component suites on X11 and Wayland at 1× and 2×. The waiver applies again;
in particular the variant-rendering budgets were measured in software only
([R094.g](verification/R094g-variant-instancing.md)).

Terrain and site tools (F03) are gated the same way at the 1.3.0 release candidate, with
the four terrain suites on X11 and Wayland at 1× and 2×. The waiver applies again: the
terrain frame and edit budgets were measured on the AMD discrete GPU
([R095.f](verification/R095f-terrain.md), [R096.g](verification/R096g-terrain-editing.md#budgets)),
and Intel graphics are untested. No other Extended row is claimed.

The 1.4.0 group (F04 to F07, `.skp` import under C01, offline coordinates under C06 and the
helper sandbox under R109) is gated as one release at its release candidate, with the native
suites that its rows name on X11 and Wayland at 1× and 2×. The waiver applies again. Two rows are
not accepted at their records: the IFC record is partial and the STEP record is partly met, and
each row states its open items.

Performance results exist for an AMD discrete GPU only
([R082.ii](verification/R082ii-amd-hardware-session.md), [R082.jj](verification/R082jj-edit-feedback.md)).
The 10,000-placement fixture fits the public limits since
[R082.gg](verification/R082gg-placement-limits.md) stopped counting placements as
unique geometry. The unique-geometry limits and the performance targets are unchanged. The Intel one-CPU frame miss
(D-004) and the Intel/Wayland open-progress gap (D-005) stay recorded and untested
at 1.0. Follow the [R082 baseline](verification/R082a-real-model-baseline.md) for
